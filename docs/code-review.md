## 已确认并修复

1. `/stop <工单编号>` 在命令注册表中可以执行，但队列只让无参数 `/stop` 走即时控制通道。有参数的中断可能等待普通对话结束。现在两种形式都走即时控制通道并共享独立的停止事件容量；不会误匹配 `/stopping`。
2. Telegram 停机只调用队列 `Stop`，未等待已经开始的处理完成，主进程可能继续关闭记忆及数据库。现在复用现有 `Shutdown(ctx)` 等待处理协程，超时会返回错误；调用者可以重试等待，避免另造一套生命周期逻辑。
