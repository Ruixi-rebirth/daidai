# 认知、模型与记忆

## 对话与工具循环

- SuperAgent 为同一会话加锁并建立处理上下文。存在工单调度器时，上下文会跟随 `agent.execution_timeout`，再预留 5 分钟用于模型收尾和持久化（默认总计 35 分钟；配置为 `0` 时不设额外 deadline）；没有工单调度器时最长 6 分钟。`/stop` 可取消发起人的在途认知、长回复续发和工单。进度消息、最终回复和错误回复都继承该处理上下文，取消后旧任务不会继续向 QQ 发声。
- Cortex 组合角色提示、当前时间、工作区说明、短期会话消息和长期画像。用户明确要求分析图片后，每轮最多保留 3 张图片交给视觉 Provider，生成最多 2,000 字符摘要，API 响应体最多读取 1 MiB；超出的图片会计数并告知模型，不可用视觉 Provider 时明确告知模型无法读图。视觉摘要和持久化用户消息均有字符上限；后台 embedding 使用与数据库一致的裁剪文本，避免向量对应未保存的尾部内容。
- QQ 附件只有在用户明确要求处理时才会读取；意图不明确或只发送附件时先询问。图片经确认后交给视觉 Provider 分析；普通文件只向模型提供名称与格式，并且 `delegate_ticket` 必须显式选择当前附件或此前待确认附件，才会下载并交给 AGY。为支持用户在追问后确认处理，进程内按发送者和会话暂存最多 10 分钟的附件 URL 与元数据，不下载或读取文件；每个会话最多保留 12 个待确认附件，超出时移除最早的附件并提示用户重新发送。确认处理成功后清除已处理附件；成功重置会话后清除该会话所有待确认附件。服务重启或过期后需重新发送。每条消息最多接收 3 个普通文件、每个不超过 20 MiB，文件存入 `data/inbox` 下按发送者、会话和单次任务隔离的目录，目录权限为 `0500`、文件权限为 `0400`；后台每小时清理超过 7 天的非活跃工单附件和超过 1 小时的遗留下载临时目录，正在下载或被运行中工单读取的目录不会被清理，暂存区最多占用 512 MiB。AGY 仅在对应任务中通过 `--add-dir` 获得该任务目录。附件内容按不可信数据处理；当前不向聊天模型直接上传非图片文件。
- 访客请求设置 `ReadOnly` 并路由到 API 兜底通道；模型的工具列表会过滤部分工程与切换工具，`HandsRegistry.Execute` 还会执行独立访客白名单检查。
- 伙伴或协作者使用非 API 首选模型时，若当前模型调用失败，路由器会尝试把本轮请求交给 API 兜底通道；本轮内容可能因此发送给 API 服务商。兜底不会改变首选模型设置，当前模型状态会显示这一行为。
- 模型最多进行 4 轮工具调用，每次认知最多执行 8 个工具调用，每组模型响应最多接受 8 个调用，单轮总计最多处理 2 个网页链接；单个工具参数上限为 64 KiB。达到调用预算后不再开放工具，只让模型整理已有结果。工具异常或无结果会作为工具响应反馈给模型。
- 每个模型返回的工具调用都必须属于该轮实际开放的工具定义；调用 ID 必须非空且不重复，工具名不可为空；模型擅自返回未开放工具时只反馈拒绝结果，不进入执行层。
- 模型自然回复及工具轮次中的助手说明最多保留 5,000 字符，适配 QQ 最多 5 条、每条 1,200 字符的被动回复上限。
- 工具返回的多张图片会一并进入回复；QQ 单次被动回复最多发送 5 条。图文超限时自动转为文字并使用“继续”分段交付；发送中断时会保留已送达与未送达部分，避免重复发送。未送完的文字在当前进程中最多保留 24 小时；普通新消息不会清除它，用户可以稍后继续，`/reset` 与 `/stop` 会清除续发内容。服务重启后，进程内续发内容不保留。
- 通用状态和延迟通知由当前模型按内容判断是否适合图卡；判断超时或失败时回退到本地结构规则。个人印象专用工具生成分页图卡；账单、网页截图等工具依输出语义返回图或文字。聊天总结先返回 Markdown，由当前对话按内容和用户偏好决定是否调用图卡工具。
- `summarize_chat` 可按自然语言总结当前私聊或本群最近最多 120 条消息，也支持只总结今天的消息；应用 `/reset` 历史边界并限制输入字符数。历史消息作为不可信资料，不会跨会话读取或执行其中的指令。
- 最终文字经过清洗；图片/卡片结果随回复发送。群聊和非伙伴私聊回复会对宿主机公网 IP 脱敏。

## 持久化与长期记忆

- SQLite 按平台分库；数据库目录和文件权限分别设为 `0700` 与 `0600`，平台名只允许小写字母、数字、下划线和连字符，避免本机用户读取会话数据及平台名形成路径穿越。
- 每条原始入站消息在进入防抖合并前按平台消息 ID 去重并写入平台 SQLite；因此认知取消、模型错误或回复发送异常不会丢掉已收到的用户正文。机器人回复仅在发送成功后写入，保存的内容已应用面向接收者的 IP 脱敏；写入失败会记录警告。slash 命令和“继续”不写正式聊天历史，避免污染总结；OAuth 授权码不记录正文。含附件的消息保存附件数量占位，不保存文件本体；完成图片分析后视觉摘要会追加到对应入站记录。空事件不入库。长期事实提炼仍在后台按内容条件独立判断。
- 长期事实保存其可见范围，并通过来源关联记录指向支撑它的用户消息；在自然语言询问某条记忆依据时，只能从当前私聊或当前群可见的范围读取来源。更新事实会替换当前依据，完全重复的事实会追加新的支持消息。
- 向量生成和长期事实提炼在后台运行，使用有超时的独立上下文。私聊只读写全局事实；群聊只读取本群事实并只能新增、修改或删除本群范围事实，避免把私聊记忆注入群聊上下文。
- 模型也可通过 `manage_memory` 手动新增、更新、删除、列出或搜索长期事实；新增会跳过同范围的完全重复事实，更新成另一条已存在事实时由数据库拒绝，避免产生重复项。搜索历史消息时限定当前会话 ID 与私聊/群聊类型，命中内容最多返回 10 条且每条截短到 200 字符。
- 后台提炼和手动记忆编辑对已有事实采用旧值条件更新/删除；若读取事实后已被并发修改，则拒绝覆盖新版本。
- 手动新增或更新的事实最多 200 个字符，由数据库写入层统一执行；注入认知上下文时，超长历史事实会截短，避免旧数据无限扩大模型提示。
- 全局 embedding 缓存按文本和编码器配置代次隔离；热切换编码器时，在途旧请求不会污染新编码器的缓存。
- 最近会话读取受 reset 游标限制；新游标用消息 ID 精确切断历史，旧游标继续按时间戳兼容；长期事实不随 `/reset` 删除。
