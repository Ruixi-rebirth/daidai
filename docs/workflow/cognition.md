# 认知、模型与记忆

群聊插话使用独立只读路径，只提供本群近期对话和成员索引，一次结构化判断决定安静、接话、碎碎念或梦境联想；不装载工作区、机器状态或人物画像。碎碎念和梦境不进入个人事实提炼输入，已发梦境的历史保留虚构标记，详见 [群内表达](group-expressions.md)。

被点名回复和主动插话共用表达规则。闲聊围绕眼前那句话，技术追问先回答当前重点，需要展开时再分段。学历和生活经历按实际回答。身份、模型和运行环境各自在被问到时说明。

QQ 消息明确点名其他群友或引用他们的发言时，不触发主动插话。网页截图收到完整发送回执后，聊天历史保留一条截图已发送的说明，消息仍只展示图片和请求所需的配文。

QQ 免 @ 续聊先按近期会话筛选候选，再用本群近期发言判断当前消息是不是在接呆呆的话。对象不明或在和别人说话时只记录消息，确认在续聊后才进入正常回答和工具流程。

## 对话与工具循环

`manage_geek_briefing` 仅核心搭档可调用，支持当前群或私聊的订阅、生成与补发；`get_geek_briefing` 同时向已订阅群的群友开放只读查看。早报整期长图、完整原文与带标题的链接索引作为确定视图交付，不再次把链接索引转成图；复合请求可保留其他问题的文字回答。归档与正常对话记忆分开，详见 [极客早报](briefing.md)。

QQ 与 Telegram 的附件意图判断支持口语表达：对象明确时，“看看说的啥”“这是什么意思”即可请求读图；只有一张可匹配图片时，“看看”也会直接查看。适用于本轮上传、引用和此前待处理的图片，无需使用专门术语。只有上传附件而没有请求、存在多个无法确定的对象，或普通文件缺少具体处理目标时，才先询问；与附件无关的问题照常回答。

- SuperAgent 为同一会话加锁并建立最长 6 分钟的处理上下文。普通 API 与 AGY 模型调用默认最多 4 分钟，仍受外层更短的上下文和主动取消约束；embedding、后台提炼等独立阶段继续使用自己的较短期限。工程工单会立即进入后台队列并返回编号；工单独立使用 `agent.execution_timeout`，排队时间不计入执行时限，也不会占住本轮对话。`/stop <ID>` 可取消指定工单，单独 `/stop` 会取消发起人的在途认知、长回复续发和全部工单；用户可在 `/tasks` 查看排队与运行状态，任务结束后收到主动通知。
- Cortex 组合精简后的角色原则、当前会话适用的群聊规则、必要的行动与来源边界、当前时间、工作区说明、短期会话消息和长期画像。记忆查询、权限管理等具体操作要求由对应工具描述与执行层承接，不在角色提示中重复维护；角色提示保留自然交流、关系边界和身份一致性等需要模型判断的原则。每轮自动注入最多 12 条与当前发言排序相关的长期事实；完整记忆仍保存在数据库，可通过 `manage_memory` 按需搜索和分页查看，避免无关画像长期占用每轮上下文。模型调用前会估算消息正文、工具参数与工具定义的总字符量；超过 64 Ki 字符时优先移除最旧的完整近期聊天轮次，保留当前请求、引用、记忆和本轮工具结果，不静默截断任务材料。该值是字符预算估算，不等同于模型 token 计数；若必要材料本身仍超限，会保留完整内容并记录警告。本轮图片与引用图片遵循同一套按需分析规则：只有图像会影响理解、判断或回答时，模型才调用 `analyze_images`。工具参数只列出本轮可读取的图片来源；如果文字足以完整处理且图片不会改变判断，可以跳过。即使请求文字看起来可能需要拒绝，只要图片可能影响请求是否适用或处理方式，仍先分析再决定。每次最多分析 3 张，调用受本轮处理期限与取消信号约束，视觉摘要最多 2,000 字符；超出的图片会计数并告知模型。该工具只使用 AGY，不依赖单独的视觉 API 密钥；不可用或失败时不声称看过图片。引用完整文字卡片时使用原文并跳过对排版图片的重复识别，混合图文中的真实图片仍可分析。视觉摘要和持久化用户消息均有字符上限；后台 embedding 使用与数据库一致的裁剪文本，避免向量对应未保存的尾部内容。
- QQ 附件只有在用户明确要求处理时才会读取；意图不明确或只发送附件时先询问。图片由统一的 analyze_images 工具按需交给 AGY 分析；获准读取的普通文件在独立字段中提供来源、元数据、读取状态及可读正文。直接读取最多 256 KiB，文本送入模型时最多保留 15,000 个字符，任一上限触发都会标记截断。 `delegate_ticket` 必须显式选择当前附件或此前待确认附件，才会下载并交给 AGY。为支持用户在追问后确认处理，进程内按发送者和会话暂存最多 10 分钟的附件 URL 与元数据，不下载或读取文件；每个会话最多保留 12 个待确认附件，超出时移除最早的附件并提示用户重新发送。确认处理成功后清除已处理附件；成功重置会话后清除该会话所有待确认附件。服务重启或过期后需重新发送。每条消息最多接收 3 个普通文件、每个不超过 20 MiB，文件存入 `data/inbox` 下按发送者、会话和单次任务隔离的目录，目录权限为 `0500`、文件权限为 `0400`；后台每小时清理超过 7 天的非活跃工单附件和超过 1 小时的遗留下载临时目录，正在下载或被运行中工单读取的目录不会被清理，暂存区最多占用 512 MiB。AGY 仅在对应任务中通过 `--add-dir` 获得该任务目录。附件正文和元数据均按参考资料处理。二进制文件本体仅按授权交给工单。
- 访客请求设置 `ReadOnly` 并路由到 API 兜底通道；模型的工具列表会过滤部分工程与切换工具，`HandsRegistry.Execute` 还会执行独立访客白名单检查。
- 伙伴或协作者使用 AGY 首选模型时，只有认证检查或进程未能启动等确定尚未执行的失败才自动交给 API 兜底；AGY 进程启动后的超时、异常或结果解析失败可能已经产生部分操作，因此停止自动重放，并明确告知用户先检查状态，避免重复副作用。只读请求直接走 API。兜底不会改变首选模型设置，当前模型状态会显示这一行为。
- 一轮回复最多执行 8 次工具调用，可分到最多 4 轮。网页读取、截图和搜索共用这份预算。`read_link` 优先让 AGY 读取指定网页并按用户原话处理。AGY 无法给出基于正文的结果时，使用受保护的 HTTP 客户端抓取正文，每次最多返回 16,000 字符，后续通过 `next_offset` 续读。`search_web` 由 AGY 搜索，必要时打开关键来源，区分已读原文和搜索摘要。搜索结果足以回答时直接使用。`screenshot_web` 只在用户要求看页面或视觉检查时调用。单个工具参数上限为 64 KiB。达到调用预算后由模型整理已有结果，工具失败会反馈给模型。
- 行动陈述必须受本轮工具结果约束：只有结果明确证明操作成功，模型才能声称已查询、计算、执行、修改、验证或发送；调用已发出、任务已排队、部分输出或失败均不能描述为完成，陈述范围也不能超过结果证明的范围。需要程序计算或外部验证的精确结果，没有成功执行依据时不得声称已运行或验证。普通知识回答和推理不附加固定免责声明；缺少执行或核实能力时，只对当前请求简短说明限制并给出可行下一步。
- 每个模型返回的工具调用都必须属于该轮实际开放的工具定义；调用 ID 必须非空且不重复，工具名不可为空；模型擅自返回未开放工具时只反馈拒绝结果，不进入执行层。生成图片后仍允许完成用户请求中的其余工具步骤，例如先截图、再读取正文并总结；统一由轮数与工具预算控制，不因已有图片提前关闭工具。
- 模型最终回复交给图片分页或文字续发流程；超过单次发送容量的文字保存在续发缓存，发送“继续”可接着看。模型输出达到 token 上限时保留已生成正文和完整工具结果，并在对应平台、会话及发起人名下保存 7 天草稿；“继续”和不带编号的 `/continue` 优先补发已生成但未送达的正文，补发完才续写草稿。只有一份草稿时直接续写，多份时列出编号。`/continue <任务编号>` 只处理指定草稿。工具已返回而模型未能生成回答时，会保存已有结果供续写。整轮超时时，只保存已收齐结果的工具轮次。续写仅开放文本生成，不重跑已完成工具。工具轮次中供模型参考的助手说明仍限制为 5,000 字符。
- 工具返回的多张图片会一并进入回复；长回复图卡按正文长度分页，不设 4 张或 10 张的应用层页数上限。QQ Markdown 临时素材在消息接受后立即删除以释放官方素材库额度；素材库触顶时只回收呆呆自己生成的旧回复图并重试。QQ 单次被动回复仍最多发送 5 条消息。图文超限时自动转为文字并使用“继续”分段交付，文字回退不附加重复提示；发送中断时只保留未送达正文，分页提示不会混入剩余内容。首次文字发送失败也会保留正文，续发失败可再次发送“继续”重试；主动取消的回复不保留。未送完的文字在当前进程中最多保留 24 小时；普通新消息不会清除它，用户可以稍后继续，`/reset` 与 `/stop` 会清除续发内容。服务重启后，进程内续发内容不保留。
- 通用状态和延迟通知由当前模型按内容判断是否适合图卡；判断超时或失败时回退到本地结构规则。个人印象专用工具生成分页图卡；账单、网页截图等工具依输出语义返回图或文字。聊天总结先返回 Markdown，由当前对话按内容和用户偏好决定是否调用图卡工具。
- 普通长回复按本地版式规则自动转成长图；用户明确要求纯文字时只跳过这一步，不把该偏好当成“内容已固定排版”，以免改变媒体回退、续发或发送期限。工具明确交付的结构化视图仍使用固定展示标记。
- 复杂流程确实适合图示时，模型可在正文中输出 Mermaid 代码块；服务端调用 Nix 包提供的 Mermaid CLI 渲染为 PNG，并在原位置嵌入回复。长回复转卡片时，Typst 也会在相同位置嵌入流程图；QQ 使用临时 Markdown 图片素材，Telegram 按正文顺序发送文字和图片。渲染禁止外部资源，并与本轮共用 1 分钟渲染时限和现有的单图 10 MiB 图片大小上限；失败时隐藏源码并保留文字回复，不限制流程图张数。
- `summarize_chat` 可按自然语言总结当前私聊或本群最近最多 120 条消息，也支持只总结今天的消息；应用 `/reset` 历史边界并限制输入字符数。历史消息作为不可信资料，不会跨会话读取或执行其中的指令。
- 最终文字经过清洗；图片/卡片结果随回复发送。群聊和非伙伴私聊回复会对宿主机公网 IP 脱敏。

## 持久化与长期记忆

- SQLite 按平台分库；数据库目录和文件权限分别设为 `0700` 与 `0600`，平台名只允许小写字母、数字、下划线和连字符，避免本机用户读取会话数据及平台名形成路径穿越。
- 每条原始入站消息在进入防抖合并前按平台消息 ID 去重并写入平台 SQLite；因此认知取消、模型错误或回复发送异常不会丢掉已收到的用户正文。机器人回复仅在发送成功后写入，保存的内容已应用面向接收者的 IP 脱敏；写入失败会记录警告。slash 命令和“继续”不写正式聊天历史，避免污染总结；OAuth 授权码不记录正文。含附件的消息保存附件数量占位，不保存文件本体；完成图片分析后视觉摘要会追加到对应入站记录。空事件不入库。长期事实提炼仍在后台按内容条件独立判断。
- 长期事实保存其可见范围，并通过来源关联记录指向支撑它的用户消息；在自然语言询问某条记忆依据时，只能从当前私聊或当前群可见的范围读取来源。更新事实会替换当前依据，完全重复的事实会追加新的支持消息。
- 长期事实提炼先在后台保存正文与来源，再补齐消息和事实向量。提炼以本轮用户自述或长期偏好为依据，引用、图片摘要和先前用户消息仅用于消歧。自然语言调整模型或思考强度时保留聊天记录，本轮跳过自动事实提炼。先前消息只读取本轮最早原始记录之前的内容。缺少入库边界时，仅使用本轮资料。后台使用 4 个固定 worker 和最多 128 条待处理队列，避免每条消息无上限地创建 goroutine；队列满时保留已保存的聊天记录，并写告警说明本轮跳过后台提炼/向量补齐。提炼与向量补齐各有 25 秒执行期限；等待同一用户的事实锁不会消耗提炼期限，停机取消会结束等待。提炼候选排序的向量请求另限 3 秒，失败时仍可使用本地关键词排序。向量补齐依靠事实原文校验更新，不持有事实修改锁。
- 模型明确选择 ADD/UPDATE/DELETE；相似度只用于召回，不把 ADD 自动改成覆盖已有事实。数据库按相同正文精确去重并关联本次来源，重复确认不会丢失新的证据。UPDATE/DELETE 必须指向本轮提供给模型且当前范围内的事实，并校验修改前原文。私聊只读写全局事实；群聊只读取本群事实并只能新增、修改或删除本群范围事实，避免把私聊记忆注入群聊上下文。
- 模型也可通过 `manage_memory` 手动新增、更新、删除、列出或搜索长期事实；同范围、同正文的新增不会重复建事实，但会追加本次来源。更新成另一条已存在事实时由数据库拒绝，避免产生重复项。搜索关键词最多 400 个字符，底层检索词也限制为 400 个，避免超长中文查询超过 SQLite 参数上限。搜索历史消息时限定当前会话 ID 与私聊/群聊类型，命中内容最多返回 10 条且每条截短到 200 字符。
- 后台提炼和手动记忆编辑对已有事实采用旧值条件更新/删除；若读取事实后已被并发修改，则拒绝覆盖新版本。
- 手动新增或更新的事实最多 200 个字符，由数据库写入层统一执行；注入认知上下文时，每轮最多纳入 12 条相关事实，超长历史事实会截短，避免旧数据无限扩大模型提示。
- 全局 embedding 缓存按文本和编码器配置代次隔离；热切换编码器时，在途旧请求不会污染新编码器的缓存。
- 最近会话读取受按会话类型保存的 reset 游标限制，使用消息 ID 精确切断历史；长期事实不随 `/reset` 删除。

每轮保留参与合并的原始入站记录 ID 列表，并由这份列表推导历史边界和回复归属。近期历史和跨场次摘要只读取本轮最早记录之前的内容，最后一条记录用于回复关联和视觉摘要更新；重置游标与历史上界同时生效。事实来源关联本轮的原始用户消息，保留合并语境，避免只剩最后一句补充；这些来源不表示每条消息都独立证明该事实。数据库逐条校验用户、平台与可见范围，任何来源不合法时整笔修改回滚。合并事件保留最新消息的授权与有效性元数据，不因合并丢失已授权访客的私聊资格。

`manage_memory source` 每页显示 5 条依据，可指定 `page` 或使用 `page_direction` 翻页；页码状态按平台、会话、用户和事实 ID 隔离。计数与当前页在同一读取事务中取得，数据库按页读取，无固定“最近 20 条”限制。没有原消息关联但有已保存摘录时，显示一条明确标注的摘录。越过末页或指定不存在的页码会返回明确说明。
