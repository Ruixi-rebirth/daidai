# 启动、消息与控制命令

## 启动顺序

1. `cmd/daidai/main.go` 从 `--config`、`DAIDAI_CONFIG` 或 `config.yaml` 读取 YAML。加载时会拒绝未知字段、多文档配置、非法服务端口、空或重复的 runner 名称、CLI runner 缺少 `{{GOAL}}` 参数模板、把整个用户主目录设为默认工作区，以及缺少必需凭据。
   OCI 日报时刻留空时默认按 `oci.timezone` 的 08:30 发送；时区留空时按 SGT。`--reset` 会在启动前清理搭档私聊的短期历史游标，因此要求配置 `qq.owner_openid`。仅当默认 `config.yaml` 不存在时才使用不启用 QQ 的默认配置；显式路径错误、其他读取失败或 YAML 无效都会停止启动。
2. 主进程先绑定健康检查端口，避免同机启动两个实例；随后在 OCI 启用时解析 PEM 并初始化客户端（限时 3 秒，失败则停止启动），再初始化出站网络护栏。
3. 创建 OpenAI 兼容 API Provider 和 AGY Provider，并注册到 `MindRouter`。访客请求使用 API 兜底通道。
4. 从 `agent.runners` 读取 AGY 命令、说明与默认目录；同一 AGY 命令贯穿模型 Provider、OAuth、视觉 CLI、网页检索、生图和表情生成。随后创建记忆引擎、可选向量模型、视觉引擎、默认工作区、AGY/CLI 工作者、工单调度器和工作区管理器。
5. `HandsRegistry` 按确定顺序注册可用工具。启动时验证的 OCI 客户端由账单和 IP 工具共用；客户端只接受长度不超过 63 字节的字母、数字和连字符 region 标识，避免 region 被拼接成非 OCI 请求域名；Nix 搜索按配置启用。
6. Cortex、QQ Channel 和 SuperAgent 组装完成后启动通道。QQ 启用且凭据存在时先刷新 Token，再运行 WebSocket 自动重连。
7. OCI 启用且 QQ 通道和 `qq.owner_openid` 已配置时，启动每日账单报告、每小时轻量费用检查和每 6 小时一次的资源巡检。资源巡检遍历租户的 compartment；卷和预留公网 IP 检查限于配置 region。日报默认按配置时区 08:30 发送；费用首次告警后，累计额每增加 `oci.cost_alert_delta` 再告警（默认 1 个计价单位）；资源风险类别按 UTC 日去重。日报尝试次数和告警状态持久化到 SQLite。主动消息通过 C2C API 发送；日报获取失败，或发送失败且未能进入待发队列时，每 5 分钟重试，连续失败 3 次后停止当天重试。发送失败但成功入队的完整报告会在用户下次私聊时投递。
   HTTP 健康检查接口供监控程序访问；在 QQ 中查看状态请发送 `/sysinfo` 或 `/status`。接口支持 GET/HEAD，并限制请求/连接时长和 Header 大小。`GET /healthz` 表示进程存活；`GET /readyz` 返回 JSON 检查项，要求 QQ 启用时网关已 READY/RESUMED、当前模型路由已配置，且 OCI 启用时调度器仍在运行。`qq_gateway` 检查的是 WebSocket 收消息链路；它断开时机器人不能通过 QQ 收到新的聊天指令，但 C2C 主动发送 API 不由此项探测，已有运行中的 OCI 日报或告警仍可能发送成功。模型项只验证本地路由已配置，不会主动调用模型 API。若 HTTP 服务意外停止，主进程执行停机清理后以失败退出。
8. 收到 SIGINT/SIGTERM 后取消根上下文，终止在途 AGY OAuth PTY 会话，再停止通道、等待 QQ 和消息 Actor 收敛、关闭 HTTP 与 SQLite。优雅停机最多等待 4 分钟，以便 OCI 不确定的变更请求完成状态核对与旧 IP 回滚；NixOS systemd 停止期限设为 5 分钟。启动阶段的目录、会话重置或通道初始化失败会以非零退出码结束。

NixOS 模块默认以专用 `daidai` 系统用户运行，`/var/lib/daidai` 同时作为其 home 与受限状态目录。宿主配置可以覆盖运行用户，因此部署时应核对最终 systemd 的 User/Group；systemd 使用 `UMask=0077`，停止期限为 5 分钟。

`services.daidai.configFile` 是运行时路径，不会复制进 Nix store。含密钥的配置应放在 `/run/secrets` 等运行时秘密目录，并允许实际服务用户读取。默认状态、数据库和 OAuth 凭据在状态目录内创建；OCI PEM 私钥或工程工作区位于其他目录时，也要授予服务用户相应权限。

## QQ 适配

- WebSocket 接受 `GROUP_AT_MESSAGE_CREATE`、`GROUP_MESSAGE_CREATE` 和 `C2C_MESSAGE_CREATE`，群聊使用群会话 ID，私聊使用用户 ID。`GROUP_MESSAGE_CREATE` 需要 QQ 平台启用全量群消息权限；未 @ 机器人的普通文字会逐条写入本群正式聊天历史，以便后续总结和记忆提炼，但默认不触发回复。纯文本群消息最多每群每 5 分钟进入一次低频插话判断；模型可选择不回复，判断不调用工具。插话通过原消息 ID 作为被动回复发送，受 QQ 被动回复时限和条数限制。未 @ 消息中的附件只暂存元数据，并在历史中留附件数量占位，不保存文件本体；后续 @ 机器人的消息明确请求处理后才读取；未 @ 的 slash 命令不会执行。
- QQ 可能把 @ 请求和附件拆成相邻事件；如果附件在请求事件后的 2 秒内到达，认知会将其纳入本轮附件授权判断，仍只会在用户明确说明处理目标后才读取。
- AccessToken 每 30 秒检查一次，并在剩余有效期不足 2 分钟时提前刷新；API 返回 401 时还会按被拒绝的旧令牌执行一次串行刷新与请求重试。
- 收到 `READY` 后缓存 `session_id` 和已接收 dispatch 序号；重连后用 `RESUME` 请求补发，传输中断时保留会话供下一次重试。会话输入队列有界；队列满时拒收当前 dispatch、保留上一条已接收序号并断开重连，避免阻塞 WebSocket 读循环，交由 `RESUME` 补发。`INVALID_SESSION` 的 `d=true` 时保留会话重试，其他/无效值时清空并重新 Identify。实际网关断线恢复仍需部署环境验证。
- QQ 入站回复携带原消息 ID；显式主动发送不携带 `msg_id`。OCI 日报和告警使用 QQ C2C 主动消息发给搭档。群聊普通对话插话必须引用触发它的群消息，不能退化成无引用主动推送；失败时记录平台错误，不伪装为成功送达。
- 被动回复失败不会自动去掉 `msg_id` 改为主动推送；Markdown 发送失败也不会换格式、换序号重发，避免接口已接收但响应丢失时重复发送。
- 长回复按 Unicode 字符数分片，跨片时按原围栏字符、长度和语言说明闭合/重开代码块；QQ 被动回复额度按入站 `msg_id` 在整个进程内累计，进度回执、通知和最终答复共享最多 5 条预算。延迟通知每轮最多发送 4 条，为当前消息的答复保留至少 1 条；当前答复超过剩余额度时发送前拒绝，避免产生部分回复后才触发平台限额。任务回执会附工单编号，便于用户用 `/task` 在新消息中查询。
- 消息 ID 进入去重缓存；最近 1000 条消息正文进入有单条长度上限的内存缓存，SQLite 引用缓存长期保留并在内存未命中时回查。出站消息同时缓存响应 `id` 和 `ext_info.ref_idx`，图片卡片优先缓存其完整 Markdown 文字版本，供后续引用还原；缓存和历史回查都校验私聊/群类型及当前会话 ID，避免跨会话引用命中。升级前没有会话范围的旧缓存不用于回查。正式对话记录也保存入库消息的平台消息 ID，可按 ID 回查。slash 命令和“继续”不写入正式聊天历史或引用缓存；OAuth 授权码也不会写入引用正文缓存。
- 解析附件图片 URL、引用正文或引用消息 ID。QQ v2 引用优先按 `message_scene.ext` 的 `ref_msg_idx` 匹配对应 `msg_elements[].msg_idx`；只有唯一引用段时才允许回退，多个候选无法匹配时不猜目标。嵌套引用最多保留 4 层，并附带作者和正文；发给模型时以结构化字段区分引用链和本轮请求，引用链总正文限 4,000 字符。引用图片会单独进行视觉分析；引用文件只提供名称和格式，只有用户本轮明确提出具体处理操作时才交给附件工单。若引用正文未随事件到达，则只在当前会话范围内从本地消息缓存查找。
- 语音消息转录支持双轨架构：极速模式（fast）优先采用腾讯官方 ASR 毫秒级直出（0ms 等待），官方未提供转录时回退多模态转录；多语精准模式（multi，默认）优先调用大模型多模态音频倾听原声（经 ffmpeg 标准化为 16kHz WAV），精准识别中/英/日等多语种且彻底杜绝平台空耳，超时或网络波动时回退官方 ASR。转录后的文本作为纯文字纳入防抖合并与认知，不作为文件附件推入后续处理。
- 当前用户消息最多进入认知上下文 12,000 字符，整条引用链最多 4,000 字符，超出部分会明确截断；历史单条消息也有相同的 12,000 字符上限。数据库写入入口和历史查询都限制消息正文长度，旧版超长记录也只读取上限加一个字符来判断是否截断，避免读取时一次性分配整段旧数据。
- 根据 `ImmuneSystem` 将发送者映射为搭档、协作者或访客。
- QQ 未授权私聊会立即返回权限提示，不进入正式聊天历史；系统仅将每个 OpenID 最近一条申请消息、昵称和时间保存在权限申请表，并主动通知核心搭档。同一 OpenID 的申请待处理期间只通知一次；主动消息失败时进入待发队列。核心搭档可自然语言查询申请与 OpenID，并在私聊中授予或撤销协作者角色；角色保存在 SQLite 并立即生效。

## 调度与控制面

- 已识别的控制指令不进入普通合并窗口，直接处理；普通控制事件和 `/stop` 有独立并发上限。未知斜杠文本与普通事件一样按“平台 + 群/私聊 + 会话 ID”进入同一个 FIFO Actor，保证不同群成员的消息按入站顺序认知；有权限的 `/stop` 与 `/reset` 会使该频道此前尚未处理的排队事件失效。`/reset` 完成前到达的后续普通消息会等待重置屏障，避免抢先读取旧历史；`/stop` 仍直接取消当前认知。
- 相邻且来自同一发送者、引用上下文相同的普通消息会在 2 秒窗口内合并；发送者或引用目标变化时先派发当前批次。每条原始入站消息在进入合并队列前按平台消息 ID 去重并独立写入历史，模型仍可收到合并后的上下文。合并累计超过 12,000 字符时，会先按序派发当前批次，再将后续消息作为下一轮处理，避免续文被截掉。每轮最多合并 64 条，达到上限后立即按序派发。每个频道 Actor 的输入和处理队列有界，输入队列满时施加背压。
- `/status`、`/sysinfo` 和自然语言状态查询优先返回状态卡片，包含进程指标和 Linux 主机 CPU 采样、内存、根分区、系统运行时间与负载；图片渲染或发送失败时回退为文字。工单详情只列当前用户、当前会话的活跃任务，不跨会话暴露目标；访客看不到工作区和工单详情，敏感 IP 会脱敏。
- `/tasks` 和 `/task <ID> [页码]` 仅伙伴与协作者可用，且只返回当前用户在当前会话发起的工单历史与输出；工单输出分页读取，避免超出 QQ 单次发送上限。
- `/model` 查看首选与备用、访客模型及准确模型 ID（路由设置不等于每轮实际调用），`/models` 列出可用模型并标注各通道已配置模型的用途，`/usage` 查看通道用量；三者仅伙伴和协作者可用。`/stop <ID>` 取消指定工单，单独 `/stop` 会中断发起人的当前认知、正在发送的长回复续发和全部工单，也会取消尚未启动的排队工单。运行工单进入 `stopping` 后仍占用并发容量，直到 Worker 退出；`/reset` 是会话级操作，会取消当前会话工单并重置工作区下所有人的 AGY 会话。权限组件缺失时这些特权命令会拒绝执行。
- 近期历史、关键词搜索和向量召回都按 `private/group` 类型及会话 ID 过滤，并共同遵守 `/reset` 游标；新游标按会话类型独立保存，读取时兼容旧版未分类型的游标。新游标以消息自增 ID 为边界，避免毫秒时间戳相同时漏读重置后的新消息。
- `/agy login/status/logout/code` 要求私聊并检查工程操作权限；`/agy logout` 同时取消等待授权码的登录会话，即使当前尚未登录也会清理会话。授权码命令不会进入消息缓存，新增消息在入库前会脱敏授权码正文。`/pwd`、`/ws`、`/cd`、`/ws rm`、`/ws clean` 管理工作区；`/voice [fast|multi]` 查看或切换语音识别模式（fast 极速 / multi 多语精准），配置持久化在 SQLite `runtime_state` 表中，且作为即时控制指令直通，不进入普通防抖等待窗口；未识别的斜杠文本进入普通认知 FIFO。
