# 群内碎碎念与梦境联想

QQ、TG 群及 TG 话题可以独立开启两种群内表达，默认均关闭，重启后保留设置。普通群聊插话照常，不依赖这两个开关。

## 自然语言管理

仅核心搭档能在当前群里管理，没有新增 slash 命令：

- “这个群开启碎碎念”：仅开启本群短感想。
- “这个群可以偶尔做梦，两项都开”：开启本群两项表达。
- “这个群别做梦了”：仅关闭梦境联想，保留碎碎念开关。
- “把本群碎碎念和做梦都关掉”：关闭两项。
- “本群碎碎念和做梦是什么状态”：查看当前群两个开关。

工具 manage_group_expressions 不接受其他群地址，权限与群聊范围在执行层检查。协作者、普通群友和私聊不能改动这些设置。

## 触发与时机

复用未 @ 群聊插话候选：收到真实群友的新消息后，安静四秒才考虑，每群候选之间至少五分钟。新消息、重置或停机会使旧候选作废。没有独立定时器，没有冷群广播，也不会因开启开关立即发一个梦。

一次只读模型判断从 skip、reply、chatter、dream 中选择：

- skip：没有具体值得说的话，保持安静。
- reply：对当前话题有帮助的普通接话，最多 300 字；必要时根据本群成员索引点名一人。
- chatter：接着近期话题的一两句主观感想，最多 100 字，不 @ 人。
- dream：由本群近期话题联想的虚构小场景，正文最多 200 字，固定以“梦到个离谱画面”引出，不 @ 人，不编写群友的现实经历。

额外表达至少需要窗口中有三条人类消息（含当前消息）。两项共用一小时冷却；梦境额外要求距上次梦境至少六小时。冷却只是频率上限，结束后仍要有新消息与合适语境，不是按时间轮流发送。讨论正忙、出现争执或在解决问题时优先普通接话或安静。

## 上下文和记忆

插话走独立只读路径，只读取当前群/话题最近最多二十条消息、最多六千字符历史，以及当前消息与本群成员索引。它不读取私聊、其他群、长期人物画像、跨场次回忆、工作区或主机运行状态；不调用工具，不读取附件或网页。

模型必须返回结构化决定。未开启、冷却中、失效候选、格式错误、超长内容或试图在额外表达中 @ 人，都不会发送。生成后再次核对开关和冷却，发送前再次核对候选有效性。

实际发送被平台接口接受后才保存冷却时间；发送失败或结果不明不会记成成功。机器人、被标记为机器人的成员及对机器人回复的候选过滤沿用平台原有机制。

已送达的梦境保留在本群聊天历史中，并标记“虚构故事，不是群成员的真实经历”，以便后续理解和追问。碎碎念和梦境正文不进入个人事实提炼输入，也不生成机器人发言的检索向量；真实群友原话仍按正常规则入库和提炼记忆。

## 存储

复用各平台数据库的 runtime_state，键为 group_expressions:<当前群或话题地址>，保存两个布尔开关和两项最近成功发送时间。原子 JSON 合并分别更新字段，避免同时调整开关与保存发送时间时相互覆盖。没有新增表、迁移代码或后台任务库。
