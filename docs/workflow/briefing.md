# 每日极客技术早报

早报作为呆呆内置能力运行，复用模型 API、Typst、QQ/TG 通道和引用缓存。默认启用工具与调度服务，但所有接收者的订阅默认关闭；不会向群或其他用户广播。

## 使用

仅核心搭档私聊可查询和管理，没有新增 slash 命令：

- “生成今天的极客早报”：后台生成并主动发到当前私聊，不占住聊天会话等待；同日已有正式版本时不再编辑。
- “今天的极客早报”：查看已归档版本，返回分页图卡和可点击原文索引。初次尚无内容时可明确要求生成。
- “每天把早报发到这里” / “关闭这里的早报”：仅更改当前平台订阅。
- “早报订阅状态”：查看各平台开关、今日生成/投递状态和下一次计划时间。
- “昨天第三条原文” / 引用早报后问“第三条”：按全期条目号读取归档，可继续使用网页工具深读原文。
- “继续早报”：补发已知剩余正文；“把今天早报完整再发一次”：重新交付已有刊物，不重新抓取。

TG 授权仍按配置用户名，不区分大小写；数字 chat_id 只作为收件地址。主动发送前通过 getChat 再核对当前用户名。QQ 仍按当前配置搭档 OpenID 核验。协作者、访客和群聊请求不能通过工具执行层绕过私聊限制。

## 生成

默认每天 08:00（Asia/Singapore）开始，自动补做窗口最多两小时，且不跨当地午夜；窗口外重启不自动补发旧刊。明确的手动请求可以在窗口外生成今日刊物。当天提前生成的版本在计划时间直接复用，发布后不覆盖正文。

四个来源：NixOS 官方公告与 Discourse、Hacker News、GitHub、V2EX。候选统一以采集结束时刻检查过去 24 小时；GitHub 新项目使用 72 小时窗口，近期维护项目不冒称今日涨幅榜。HN 时间是提交时间，不保证原文也在这一天发布。

全局 HTTP 并发最多六个，每个来源的并行任务最多三个；候选采集与补料共享 60 秒期限，响应体解压后最多 2 MiB。HTML 使用 HTML5 解析器，README 使用 Markdown 解析器去掉杂项，不通过正则剥标签，不启动浏览器或逐条 AGY。

代码过滤、合并重复与七天内已推荐内容后，最多 24 个候选交给一次只读 API 编辑。GitHub 为新项目和近期维护项目分别保留候选机会，避免总 Star 较高的老项目挤掉新项目。入模只包含编辑必需字段，总输入最多 40,000 字符，必要时统一缩短各条摘录，而不是把最后一个栏目全部删掉。

模型最多选择 12 条，栏目上限为 NixOS 3、HN 4、GitHub 3、V2EX 2。标题以 30 字为目标，上限 60 字以容纳完整项目名；摘要目标 45–80 字，版面上限 120 字。过长摘要只取完整句子，不硬截半句。原始标题、材料类型、摘录、指标和链接保存在归档；模型不能替换原文链接。只有标题的材料强制不生成摘要。

输出中未知、重复或超过栏目额度的条目会被丢弃，保留其余有效条目；JSON 不可用或完全没有有效选择时，发布最多六条的基础速览。单源故障不阻止其他栏目。全部来源失败会记录失败并在窗口内有限重试，不假装当天没有新闻。合法空刊只发简短文字，不发空图卡。

## 图卡和引用

440pt 单列窄版、18pt 正文，每页最多三条，最多四页，显示 `[1/4]` 页码。图卡、链接索引、文字回退均来自同一期结构化数据；原文索引不交给模型改写，不附加重复说明。若用户还提出其他问题，工具的 only_briefing=false 会保留那些回答。

每张图保留该页原文，TG 相册单页和 QQ 单独图片可恢复对应正文；QQ 合并多图本来是一条平台消息，引用它恢复整期，不猜用户点了哪张图。自己的渲染图有完整原文时不再 OCR。

全期编号发布后固定，跨页不重新编号。未指定日期时优先引用中的刊物日期，再使用当前私聊最近成功展示的刊物；/reset 清除这个指代，但不删除历史刊物。真正送达的图卡正文才进入聊天历史，不伪造用户入站消息，不把新闻提炼成个人事实。

## 存储与投递

共享 data/db/briefing.db，独立三张表：brief_editions、brief_subscriptions、brief_deliveries。SQL 约束保证刊物日期、平台/收件者及投递唯一性；同日并发生成合并，两个平台共享刊物但分别投递。模型失败后的基础速览也是当天正式版本，普通查看不会再次花费编辑调用。

发送前先准备完整图卡；渲染失败退回文字。媒体准备阶段明确尚未尝试发送消息时，可安全退回文字；消息请求已提交但回执不明时不再从头换格式发送。

明确可重试的平台拒绝最多自动尝试三次、至少间隔五分钟，并尊重 Retry-After；永久拒绝不持续重试。部分成功保存已送与剩余正文，补发默认只发剩余文字。超时或崩溃时处于 sending 的记录保守标记 uncertain，不声称本地唯一键能保证平台端恰好发送一次。

主动推送和手动查看共用投递记录，失败状态保留，不再交给通用续发缓存重复补发。搭档下次私聊时仅提示最近一期异常一次，不连发多日早报。手动完整查看成功会清除该期剩余投递状态。/stop 取消当前私聊的在途早报，并暂停该接收者当天自动重试；显式再次生成或重新开启订阅可恢复，长期订阅不会因此删除。

## 配置和验证

briefing.enabled 默认 true；timezone 默认 Asia/Singapore；time 默认 08:00。github_token 可选，沿用 YAML/sops，不在配置里另外维护一份收件人名单。将 enabled 设为 false 会停止注册工具和启动早报服务。

/readyz 的 geek_briefing 项只表示调度生命周期正在运行，不主动访问新闻源或模型。普通测试使用 HTTP 和模型夹具；真实来源/模型测试需显式设置 DAIDAI_LIVE_TEST_CONFIG，且只生成临时刊物，不发送消息或修改在线订阅。

设计来源与样张见 [设计记录](../design/geek-briefing.md)。真实 QQ/TG 的主动发送仍受平台权限、连接与配额约束，以投递记录和客户端收到的结果为准。
